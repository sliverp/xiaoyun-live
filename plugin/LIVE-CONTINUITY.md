# 持续直播与多端控制

导演台上方显示本机角色、当前播报电脑、在线控制端、直播轮次、上次音频进度和自动恢复次数。已登录的控制端每2.5秒读取同一份服务端状态，可远程暂停、继续、结束或从头播报。监控电脑点击“重新开始”保留原播报电脑；只有明确点击“接管播报”才转移声音。OBS 继续抓取原播报电脑的网页与声音，监控电脑默认静音。浏览器重新加载后如未获得播放授权，需在播报电脑点击“接回播报”；后台不能绕过浏览器的声音权限。

“持续直播与自动抽奖”在开播前保存。当前部署启用无声恢复、循环播放和每轮独立模型会话；自动抽奖默认关闭，待场控设置实际规则与奖品后启用。

## 无声恢复与循环

播报端心跳上传当前口播、音频片段编号和播放位置。连续120秒没有前进的播放位置或整段完成确认时，控制器取消卡住的文案、预合成和音频，创建新的模型会话并尝试恢复当前页；每次恢复重新开始计时，避免密集重试。监控端的在线心跳、生成完成或重复的音频时间戳都不算声音进度。模型失败、TTS错误和断连等待均可进入此恢复流程；人工暂停及立即停止不会被自动恢复。

开启循环时，最后一页讲完且已排队抽奖处理完后，HTML 演示页重新打开到第一页，文字素材回到第一页。自动续播不反复念开场和告别；手动“重新开始”重新念开场，手动“结束并告别”才念结束语。两种重播均保留已发奖品、中奖记录、自动抽奖触发记录和播报电脑。未开奖的参与窗口中断时不猜测结果；已经确定的结果可重播，不能重新抽人或再次扣奖品。

服务端 `live-runtime.json` 原子保存播报意图、原播报端、人工暂停、轮次和恢复记录。服务重启后，原播报端及监听重新在线时可恢复；人工停止的直播不会自行开始。浏览器关闭、电脑休眠、OBS停止或视频号掉线仍需要恢复对应设备；服务器不能代替已关闭电脑输出声音。

## 有界模型上下文

当前部署 `contextMaxTurns: 1`：每次文案请求使用独立 DSH 会话，前一个创建句柄通过 `dispose()` 释放内存、注册项和运行资源。旧会话日志保留在磁盘，不再作为后续模型请求的对话历史。主备模型切换继续使用本轮明确的素材与规则。

每轮重新加入小云身份、系统提示词、当前页正文与对应补充笔记、该页已讲段数、已播要点摘录、最新直播指标和持续奖品记录。当前页最多保留32条、每条60字的要点摘录，以及最近4段、每段220字的口播摘录；换页时清除上一页摘要与旧口播衔接文本，未播出的预生成稿不能当作已播内容。

候选弹幕仅取最近120秒内未回应的最新100条。候选 JSON 另受24,000 UTF-8字节输入预算约束；遇到大量超长弹幕，进一步舍弃较早项，保留最新项的完整昵称和消息。抽奖口令匹配与完整数据导出不受此模型输入预算影响。控制台显示本轮素材字符数；它不包含框架额外系统段落，不冒充模型精确 Token 数。

## 自动抽奖与奖品池

支持三类规则，可同时启用：北京时间每天指定时刻、按间隔分钟（60为每小时）、最新热度或在线人数达到阈值。指定时刻支持两分钟触发宽限；人气值必须是最近30秒采集到的真实值，不使用历史峰值或推测值。阈值规则每次配置只触发一次，间隔按开播时的起点计时；重播不重新计时。多条规则同时达到时合并为一次抽奖。

满足条件后将抽奖排在当前整段口播之后，不截断当前句子，也不立即抢走声音。已有抽奖进行时持久保存已观察到的触发条件，结束后再插入，即使人气随后回落也不会丢失；错过多个间隔时只处理最近一期，不补发一串过期抽奖。触发标识在排队前原子写入 `live-lottery-schedule.json`，防止重连或服务重启重复发奖；极端情况下在写入标识之后、排队之前进程退出，可能跳过该次触发，不重复发奖。

奖品池一行一份，可重复名称，最多500份。已发部分不可删除、改名或重排；可追加奖品或调整未发部分。奖品发完后自动跳过并显示原因，不因为循环、恢复、改规则或重启而自动补奖。追加后的奖品数量以运行时记录为准，不沿用旧活动文案中的数量。

验证：`node --test lib/live-automation.test.mjs lib/live-long-running.test.mjs lib/live-monitor-client.test.mjs`。虚拟时钟验证48小时、5,760轮讲解与48个整点间隔，不等同于已完成真实48小时在线压力测试。
