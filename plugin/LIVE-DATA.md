# 直播数据采集与导出

Mac 监听器读取已登录的视频号直播后台响应，并识别直播大屏上可见的指标卡片，默认每 5 秒生成一个时间切片。数据通过既有认证上报链路送到服务器；Cookie、请求头、完整接口响应与个人账号资料不上传。API 数值优先于舍入显示值，DOM 采集保留原始显示值与来源标签。

指标包括在线人数、平台最高在线、热度、累计观看人数、观看次数、点赞、分享、新增关注、礼物微信币、开播时间与直播时长。具体可用项以后台实际提供的数据为准，未提供的字段保持为空。暂未识别的数字统计字段以 API 字段路径保存在 `extra` 中；它们不自动变成具有推测含义的指标。消息记录包括文字弹幕与平台明确标记的进场、点赞、礼物事件；点赞事件数不等于用户精确点赞次数。

每轮模型请求都附带最新可用指标、采集时间、观测在线/热度峰值、已采集弹幕数量与观测时长。数据作为口播请求的一部分进入 DSH 会话记录，便于核对小云当时看到的内容。超过 30 秒未更新的指标不作为当前值给模型；提示词要求不猜测缺失数据、不重复播报数字，也不将独立评论者数误认为观众总数。

视频号直播场次与小云播报区间分别记录。停止、告别或异常暂停小云时生成阶段报告，但继续采集视频号数据；后台 `liveInfo.liveStatus` 为 `2` 时结算整场报告。断连不等于结束，新直播 ID 会开启新记录。监听中途接入无法恢复此前的时间切片，观测最高在线与平台自身提供的最高在线分开列出。

导演台的「直播数据导出」可选择当前或历史场次，下载以下三种文件，采集中也可导出。

- **完整数据 JSON**：汇总、指标定义、全部时间切片、弹幕与互动明细。
- **时间切片 CSV**：UTC 时间、在线与其他指标、原始显示值、字段采集时间、API/DOM 来源、舍入标记、是否连接、小云状态、演示页码与额外统计字段。缺失值为空，CSV 字符串防止公式执行。
- **汇总报告 Markdown**：观测最高在线、最高热度与峰值时间、平台累计指标、观测平均在线及其有效覆盖秒数、平台与采集时长、弹幕数量、评论者 ID 数和小云播报区间。统计口径随报告导出。

服务器持久化目录为语音工作区下的 `live-analytics/<记录 UUID>/`，包含 `session.json`、`snapshots.jsonl`、`events.jsonl`、`summary.json` 和 `report.md`。JSONL 逐条追加；重启时恢复时间切片、峰值和消息去重，未完成的末尾追加会截掉。Mac 的 `metrics-outbox.json` 保存尚未被服务器确认的时间切片，短暂网络断开或监听器重启后继续发送。记录与导出只允许已登录的场控访问。

Mac `config.json` 中的 `metricsIntervalMs` 可设置为 1000–60000，默认 5000。桥接器与插件共享 `plugin/lib/live-metrics.js` 中的指标定义，因此应保留现有 `live-bridge/` 与 `plugin/` 相邻目录结构。采集不操作视频号的开始/结束直播按钮。

验证命令：`node --test ../live-bridge/parser.test.mjs ../live-bridge/metrics.test.mjs lib/live-analytics.test.mjs lib/live-mode.test.mjs lib/live-lifecycle.test.mjs`。尚未正式开播时只能验证采集解析、回放与导出链路，实际字段可用性需要下次开播核对。
