# 实现方案

项目目标是让 AI 虚拟形象成为可对话、可持续讲解、可回应观众并接受场控指挥的直播参与者。网页演示稿是它的内容输入之一。

## 一次完整口播

服务端根据当前状态决定欢迎、讲解、弹幕回应、互动或活动。模型收到固定身份、当前环节、当前页、相关笔记、有界摘要与新弹幕，返回结构化的口播和导航意图。调度器负责执行和确认，模型不直接持有浏览器登录凭据。

文本按句末优先切片，送入 TTS 队列；当前片段播放时合成后续片段，最多预备下一轮。音频播放进度驱动嘴部开合。整轮确认完成后才切到读弹幕、翻页或活动，避免在一句话中间插入别的环节。预备内容因新弹幕或场控指令失效时，丢弃并重新生成。

## 持续运行

状态、活动记录与播报意图在服务器持久化；多端控制同一状态，只有播报端拥有音频租约。每轮模型使用独立短会话，身份持续注入，旧请求结束后释放相应 Agent 对象，保留当前页和有界摘要；候选弹幕最近两分钟、最多 100 条。录音和获奖记录的保存与模型上下文淘汰相互独立。

模型主备负责请求失败与超时，120 秒音频进度看门狗负责调度或播放卡住。后者只在仍希望开播且未暂停时恢复，不代替人工重新开播。时钟触发只排队，等整段播完后进入；二维码浮层独立于页码，可跨页保留并自动到期收起。

## 数据与限制

浏览器桥读取已登录后台的实际响应与可见指标，不获取登录 Cookie。导出的每个时间切片保留观测时间、来源、缺失信息和播报状态。观测最高在线与平台最高在线分别表达，独立评论人数不代替总观众数。

现阶段是单房间实现；页面协议变动、翻页适配、模型对主题讲解是否过度、音频输出设备与 OBS 都需要实际场景验收。48 小时虚拟时钟测试验证调度与输入有界性，不是 48 小时真实无故障承诺。
