# 部署

本项目采用云端 Agent 与本机采集、播报分工。Linux 服务器负责 DSH、语音识别、模型调用、语音合成、持久化和 HTTPS；Mac 负责登录视频号、读取演示页与后台数据；浏览器播放声音和渲染人物，OBS 最终推流。

## 服务器

示例资源为 4 核 8GB、Linux、Docker Compose。ASR 使用 SenseVoice INT8 CPU 模型。`compose.yaml` 使用 Linux host 网络；应用和 ASR 分别只绑定 127.0.0.1:13081、127.0.0.1:10095，不直接暴露。公网只需要 HTTP 80 与 HTTPS 443，SSH 应仅对维护来源放行。

1. 复制 `.env.example` 为 `.env`，设置域名、模型主备接口与密钥。
2. 在仓库之外的 `/etc/xiaoyun-live/tencent-tts.json` 配置已开通 TTS 的账号凭据，将目录设为 0700、文件设为 0600。可通过 `TTS_CREDENTIALS_DIR` 指定其他独立目录，建议独立最小权限子账号。
3. 下载模型，再运行 `docker compose up -d --build`。
4. 从本机私下读取应用启动日志中的登录链接，使用自己的公网域名打开。日志含登录令牌，不上传工单、仓库或公开附件。
5. 验证 `/healthz`、`/live-demo/`、控制台登录、麦克风权限及一轮真实语音问答。

首次启动创建独立数据目录与通用人设，不复制已有服务的会话和凭证。`deploy/configure.mjs` 管理模型与插件部署参数；启动时以 `.env` 为准。用户在控制台修改的直播素材和活动记录位于 `data/voice-call/`，不会因容器重建丢失。

## 本机与 OBS

安装 `live-bridge/`，在本人扫码登录的 Chrome 上连接视频号后台。控制台填入 HTML 演示页地址；`/live-slides/` 提供通用示例。绿幕人物和演示画面分别采集，保持 OBS 播报浏览器处于允许播放声音的状态。

同一部署只由一个浏览器播报，其他登录设备监控并控制同一个服务端状态。暂停会保留进度，重新开始重置内容进度但保留奖品记录；结束整场会告别后停止，立即停止会中断。循环不会反复播放开场和告别。

定时活动、二维码和素材必须使用自己的业务内容。仓库中部分固定口播是开发演示样例，不代表当前仍在进行的活动。

## 升级与验证

先备份私有 `data/` 与部署配置，验证新版本后再替换镜像。不要在正在播报时无提示重启。模型主通道默认 10 秒超时、备用 30 秒，失败通道冷却后再探测；音频无进度达到 120 秒尝试恢复。人工暂停、停止不被自动恢复撤销。

公开展示页属于静态交互演示；只有控制台授权后启动的语音对话与直播是实时模型执行。
